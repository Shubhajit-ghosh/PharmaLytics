Comprehensive PharmaLytics Mission, Architecture, Workflow, and File Catalog

🧬 Name of the Project

PharmaLytics — A secure, role-based pharmaceutical data operations, customer relations management (CRM), and performance analytics platform.

🎯 Mission

To empower pharmaceutical sales organizations with real-time data transparency, structured hierarchical oversight, and secure transactional pipelines. PharmaLytics bridges the gap between field representatives, district managers, and corporate administrators by converting raw transaction logs into high-fidelity actionable intelligence.

👁️ Vision

To establish a premium, zero-trust standard for pharmaceutical sales operations, facilitating seamless global-to-local target tracking, validation checkpoints, and forecasting pipelines that drive commercial excellence.

💡 What was the need to create this project?

Prior to PharmaLytics, pharmaceutical companies faced significant operational challenges:

  • Disconnected Field Reporting: Representatives lacked a validated channel to submit daily unit sales, leading to delayed or inaccurate reporting.
  • Lack of District Governance: District managers could not efficiently track reps reporting under their territory or allocate performance targets locally.
  • Data Integrity & Fraud Risks: Direct database edits bypass audit gates. Secure approval workflows were required to verify sales submissions.
  • Target Tracking Gaps: Corporate administrators struggled to allocate manager target goals down to representatives, resulting in target misallocations.

🔄 Workflow Channels

1

Authentication & Workspace Initialization

Users choose their roles (Admin/Manager/Rep) and type username/password. The frontend initiates local sessions and scopes layout views dynamically.

2

Sales Entries logging

Representatives log sales records in their workspace. Submissions are marked with a Pending status inside the SQLite database.

3

Verification Gate & Analytical Calculation

System administrators review and approve pending records. Once updated to Approved, the fact transaction data is aggregated to trigger dynamic dashboard calculations and forecasting charts.

Frontend Javascript Controllers (`app.js`)

Function Name Purpose / Action Critical Dependency (If missing, what would break?)
resolveChartDefaults() Applies global font/theme configurations to Chart.js context. Charts would draw with default styles, resulting in visual rendering bugs under dark theme mode.
formatCurrency(value) Converts values to formatted text (e.g. $1.20M). Metrics would show raw, unreadable numbers on dashboard KPI cards.
safeFetch(url) Executes API calls inside safe try-catch wrappers. Unhandled network errors would crash page loading, making error tracking difficult.
getFilterParams() Collects dropdown filter states as URL queries. Filtering options would not pass parameters to the API, causing charts to show unfiltered data.
initNavigation() Coordinates transitions between sidebar layout panels. The application would not navigate between pages, sticking only to the dashboard.
loadDashboardData() Refreshes analytics, KPIs, and Chart.js dashboards. Overview charts and analytics summary stats would remain empty.

initManagerTeamView(...) Fetches reps reporting to manager and binds filters. Managers could not view progress metrics for specific team representatives.
initTargetsTracker() Loads target metrics, checks limits, and configures goals. The target tracking page would fail to load target cards.
showCustomConfirm(...) Renders styled confirmation/alert pop-up modals. Confirmation dialogs would fall back to default browser boxes, degrading UI aesthetics.

Backend Service Routes (`backend/app.py`)

Route endpoint Backend Operation Critical Dependency (If missing, what would break?)
GET /api/kpis Computes actual revenue and unit sums over dynamic filters. KPI summary figures at the top of the dashboard would display no data.
GET /api/forecast Computes regression forecast parameters for linear predictions. The forecasting section of the line chart would fail to draw.

Key Development Challenges

A record of major architectural bottlenecks, resolutions, and professional prompts used during the development of PharmaLytics.

CORS Preflight Blocks on DELETE Operations

Issue: Browser CORS preflight security checks blocked custom HTTP verb (DELETE) requests fired from the frontend client to the Flask backend dev server.

Resolution: Expanded the allowed CORS header methods inside the Flask backend connection hook to include DELETE and PUT, and adapted frontend deletion endpoints to accept safe fallback POST requests.

Prompt: "CORS security headers block target deletion requests. Update Flask CORS method headers to include DELETE, and map deletion controllers to accept fallback POST routing."

Horizontal PDF Layout Splitting & Height Truncation

Issue: Capturing wide dashboard DOM structures (width: 1000px) directly caused html2pdf.js to split the document horizontally across portrait layouts, creating blank space and missing table pages.

Resolution: Compiled the report elements dynamically inside an isolated `750px` width compiler container, locked tables with table-layout: fixed, and instructed the PDF generator to split pages using CSS directives.

Prompt: "html2pdf splits wide tables horizontally. Constrain print container width to 750px, force fixed table layouts, and wrap long table cell words dynamically."

Multi-Role Targets Conflict

Issue: Administrators setting representative goals directly bypassed district managers' hierarchy, creating conflict and data clutter.

Resolution: Restructured target scopes: Administrators set goals for corporate and managers; Managers assign, edit, and delete goals for representative sales teams.

Prompt: "Enforce role delegation: managers assign/edit targets of reporting reps; admins manage company goals and managers targets only."

Closest Selector Crash on Target Page Load

Issue: The JavaScript execution crashed with a TypeError when loading targets tracker because selectors queried `.closest('.kpi-card')` which was missing from the redesigned targets cards.

Resolution: Updated the DOM search selector class from .kpi-card to `.card` in targets renderer blocks.

Prompt: "Fix TypeError: Cannot read property closest of null on targets page. Update card selector from kpi-card to card."

Native Browser Confirmation Dialog Replacements

Issue: Browser-native alert and confirmation popups disrupted the custom dashboard theme and looked unprofessional.

Resolution: Created an overlay container `#generic-confirm-modal` in HTML and bound it to a custom async handler showCustomConfirm() to replace native dialogs with styled overlay confirmations.

Prompt: "Replace the delete warning error with a custom modal confirmation interface, converting all native browser confirm and alert boxes to styled modals."

Font Scaling & Accessibility Bounds

Issue: Restructuring settings views required providing text resizing boundaries strictly isolated from metrics-card borders.

Resolution: Bound buttons in Settings to toggle custom body HTML class mappings (font-sm, font-md, font-lg) and defined relative sizes using rem units.

Prompt: "In the settings view only, add controls to change the font size of the webpage and generate account credentials, keeping management sections isolated."

Zero-Trust Default Password Enforcement

Issue: System security was compromised if representatives could login indefinitely using default auto-generated passwords.

Resolution: Added database status checkers to prompt users on login if their accounts utilized default credentials, forcing redirects to the password config screen.

Prompt: "Force reps with default credentials to change passwords. Add complexity validation requirements (uppercase, lowercase, number, special char) for new passwords."

Aesthetics De-cluttering & Visual Brand Realignment

Issue: The initial platform design used teal-purple gradients, generic line icons, and excessive padding, giving it a generic "AI SaaS dashboard" feel rather than a professional enterprise data app.

Resolution: Cleaned typography using Inter and Plus Jakarta Sans, simplified borders, and set the dominant brand primary color to Deep Medical Blue (#164E63).

Prompt: "Kill the modern SaaS startup look. Align PharmaLytics design with a healthcare-oriented data analytics and CRM tool. Adopt Deep Medical Blue (#164E63) as the dominant primary brand color."

Sidebar Toggle Collapse Alignment & Chart Reflow Observer

Issue: Transition animations on navbar collapse/expand actions created latency. Chart.js calculations executed before the content card width settled, resulting in cut-off graphs.

Resolution: Synchronized both `width` and `margin-left` transitions in CSS, and bound a high-performance, native ResizeObserver on the main content wrapper in JavaScript. This triggers real-time Chart.js scaling frame-by-frame as the layout changes size.

Prompt: "Resolve graph misalignment and clipping on navbar collapse toggles. Ensure all charts auto-reflow and align perfectly as the sidebar slides open/closed."

PharmaLytics is an enterprise-grade analytics, customer relations management, and compliance validation platform tailored for pharmaceutical commercial teams. The platform consolidates regional pharmaceutical transactions, doctor purchase patterns, and drug product catalogs, transforming raw daily reports into structured analytical insights.

To establish strict transactional transparency and validation checkpoints across all levels of pharmaceutical field sales operations. We aim to replace manual spreadsheets with zero-trust validation gateways, allowing direct data accountability between representatives, managers, and corporate admins.

Corporate Vision

To stand as the trusted standard for pharmaceutical commercial analytics and auditing. By combining responsive data modeling with role-based dashboard delegation and regression-based sales forecasting, we equip companies with tools to align local district activities with overall global targets.
